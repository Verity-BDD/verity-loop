## ADDED Requirements

### Requirement: Создание папки сессии
При запуске харнесса система SHALL создавать папку сессии в `.verity-sessions/<timestamp>/` рядом с `verity.yaml`. Временная метка форматируется как `2006-01-02T15-04-05Z` (UTC, двоеточия заменены дефисами для совместимости с файловыми системами).

#### Scenario: Успешное создание
- **WHEN** харнесс стартует и `configDir` доступен для записи
- **THEN** создаётся директория `.verity-sessions/2006-01-02T15-04-05Z/` и система готова принимать артефакты

#### Scenario: Ошибка создания директории
- **WHEN** директория `.verity-sessions/` недоступна для записи (нет прав, нет места)
- **THEN** харнесс логирует предупреждение и продолжает работу без записи артефактов (сессия проходит в штатном режиме)

### Requirement: Создание папки итерации
Для каждой итерации цикла система SHALL создавать поддиректорию `iteration-<N>/` (N — двузначный ноль-паддинг, например `iteration-01`).

#### Scenario: Создание папки первой итерации
- **WHEN** начинается итерация 1
- **THEN** создаётся `iteration-01/` внутри папки сессии

#### Scenario: Создание папки десятой итерации
- **WHEN** начинается итерация 10
- **THEN** создаётся `iteration-10/` и она лексикографически сортируется после `iteration-09/`

### Requirement: Запись промта
Система SHALL записывать полный промт, отправленный агенту, в `iteration-<N>/prompt.md` до вызова агента.

#### Scenario: Промт записан до запуска агента
- **WHEN** промт сформирован и агент ещё не запущен
- **THEN** `iteration-<N>/prompt.md` содержит полный текст промта

### Requirement: Запись вывода агента
Система SHALL записывать stdout+stderr агента в `iteration-<N>/agent.log` в реальном времени — каждая строка пишется сразу после получения от subprocess.

#### Scenario: Потоковая запись
- **WHEN** агент выводит строку
- **THEN** строка немедленно дописывается в `agent.log` (без буферизации до завершения агента)

#### Scenario: Агент не вернул вывода
- **WHEN** агент завершился без вывода в stdout/stderr
- **THEN** `agent.log` существует, но пуст

### Requirement: Запись вывода тестов
Система SHALL записывать полный raw-вывод тест-команды в `iteration-<N>/test.log` после завершения теста.

#### Scenario: Тест упал
- **WHEN** тест-команда завершается с ненулевым exit code
- **THEN** `test.log` содержит полный вывод команды (stdout+stderr)

#### Scenario: Тест прошёл
- **WHEN** тест-команда завершается с exit code 0
- **THEN** `test.log` содержит вывод команды

### Requirement: Запись диффов сервисов
Система SHALL записывать git-диффы каждого сервиса в `iteration-<N>/diffs/<service-name>.patch` в начале итерации (до запуска агента, отражает изменения накопленные с baseline).

#### Scenario: Несколько сервисов
- **WHEN** в конфиге определены сервисы `frontend` и `backend`
- **THEN** создаются `diffs/frontend.patch` и `diffs/backend.patch`

#### Scenario: Сервис без изменений
- **WHEN** diff сервиса пуст (нет изменений с baseline)
- **THEN** файл `.patch` создаётся и содержит пустую строку или пустой контент

### Requirement: Запись rollback-диффа
Если итерация завершилась откатом, система SHALL записывать diff изменений агента в `iteration-<N>/rollback.patch` до того, как откат выполнен.

#### Scenario: Rollback выполнен
- **WHEN** liveness-check провалился и харнесс откатывает изменения
- **THEN** `rollback.patch` содержит diff изменений, которые были откачены

#### Scenario: Rollback не выполнялся
- **WHEN** итерация завершилась без отката
- **THEN** файл `rollback.patch` не создаётся

### Requirement: Запись результата итерации
Система SHALL записывать `iteration-<N>/result.md` после завершения итерации, содержащий: статус (PASS / FAIL / ROLLBACK / TIMEOUT), продолжительность итерации, и краткое резюме.

#### Scenario: Итерация завершилась PASS
- **WHEN** тест прошёл в данной итерации
- **THEN** `result.md` содержит `Status: PASS` и продолжительность

#### Scenario: Итерация завершилась ROLLBACK
- **WHEN** liveness-check провалился
- **THEN** `result.md` содержит `Status: ROLLBACK` и продолжительность

#### Scenario: Итерация завершилась TIMEOUT
- **WHEN** агент превысил таймаут
- **THEN** `result.md` содержит `Status: TIMEOUT` и продолжительность

### Requirement: Финализация сессии
По завершении харнесса (PASS, FAIL или сигнал) система SHALL записывать два файла в корень папки сессии.

`session.md` — человекочитаемое резюме:
- Итог (PASS / FAIL)
- Продолжительность сессии
- Количество итераций / max_iterations
- Путь к конфигу

`session.json` — машиночитаемые метаданные:
- `outcome`: "pass" | "fail"
- `started_at`: ISO 8601 UTC
- `ended_at`: ISO 8601 UTC
- `duration_seconds`: число
- `iterations`: число выполненных итераций
- `max_iterations`: лимит из конфига
- `config_path`: абсолютный путь к `verity.yaml`

#### Scenario: Сессия завершилась PASS
- **WHEN** тест стал зелёным
- **THEN** оба файла записаны с `outcome: pass`

#### Scenario: Сессия завершилась FAIL (исчерпаны итерации)
- **WHEN** достигнут `max_iterations` без зелёного теста
- **THEN** оба файла записаны с `outcome: fail`

#### Scenario: Сессия прервана сигналом
- **WHEN** харнесс получает SIGINT/SIGTERM
- **THEN** система делает попытку записать финальные файлы перед завершением
