## ADDED Requirements

### Requirement: Префиксированный вывод
Харнесс SHALL выводить все события в stdout с цветными префиксами, однозначно идентифицирующими фазу.

#### Scenario: Событие инициализации сервиса
- **WHEN** харнесс запускает сервис
- **THEN** строка начинается с `[INIT]` (жёлтый)

#### Scenario: Событие liveness-проверки
- **WHEN** харнесс проверяет liveness сервиса
- **THEN** строка начинается с `[LIVE]` (зелёный при успехе, красный при неудаче)

#### Scenario: Событие тестирования
- **WHEN** харнесс запускает или получает результат теста
- **THEN** строка начинается с `[TEST]` (зелёный при pass, красный при fail)

#### Scenario: Событие агента
- **WHEN** харнесс запускает агента или получает строку его вывода
- **THEN** строки запуска начинаются с `[AGENT]`, строки вывода — с `[AGENT] >`

#### Scenario: Событие перезапуска
- **WHEN** харнесс перезапускает сервис
- **THEN** строка начинается с `[RESTART]` (жёлтый)

#### Scenario: Событие остановки
- **WHEN** харнесс останавливает сервис при teardown
- **THEN** строка начинается с `[STOP]`

### Requirement: Прогресс liveness polling
Харнесс SHALL выводить прогресс liveness polling, не спамя лог. Прогресс логируется не чаще чем раз в 5 секунд.

#### Scenario: Сервис долго поднимается
- **WHEN** liveness polling длится более 5 секунд
- **THEN** харнесс выводит промежуточный статус с количеством прошедших секунд
